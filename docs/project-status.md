# 项目状态与路线图

## 当前版本：0.3.0-dev（可靠任务与多渠道基础）

当前版本在可靠任务 MVP 上完成了 v0.3.0 的迁移、事务、租约、资源隔离、模式策略与敏感信息审计修复；并开始 P1 的多渠道基础设施。它仍不是功能完整或高可用生产平台。

## 已实现

### 可靠消息与安全边界

- 企业微信客服回调验签、AES 解密、URL 验证与 `sync_msg` 分页拉取；
- PostgreSQL 持久化 Outbox、有限重试、指数退避、死信、人工重放、补偿扫描；
- 任务领取 `lease_token`、续租与旧 Worker 栅栏，避免过期 Worker 覆写新任务；
- 入站消息幂等、用户 HMAC 检索、原始标识与私密内容加密保存；
- `/clear confirm` 只清理历史记录，保留当前命令的事务关联；
- 外部投递前持久化投递栅栏：投递状态未知时不自动补发，避免重复回复；
- Provider、角色卡、预设均校验资源所有者；异常、死信与日志统一脱敏；
- 长推理默认等待 300 秒；空模型响应进入可靠重试，不向用户伪造“没有内容”的成功提示。

### 用户能力与双模式

- 每用户独立会话、模型名、人设、温度、上下文、最大输出、记忆开关与每日配额；
- 角色卡、预设、私有记忆、BYOK Provider 数据模型；
- `/help`、`/status`、`/model`、`/persona`、`/temperature`、`/context`、`/new`、`/clear`、`/memory`、`/usage` 等命令；
- `single`、`self_service`、`managed` 模式及命令策略覆盖；
- 管理统计、用户模式、死信重放、封禁与最小化用户数据视图。

### P1 多渠道基础（本阶段）

- 渠道适配器协议与进程内注册表；新渠道只能通过统一 `ChannelMessage` / `OutgoingMessage` 进入服务层；
- `wechat_clawbot` HTTP 桥接适配器，具备实例启动、停止、文本发送契约；
- 管理 API：渠道实例创建、查询、启动、停止；公开实例配置拒绝 `token`、`cookie`、`password`、`secret` 等敏感字段；
- 独立桥接 Bearer 鉴权：桥接入站接口不复用管理员令牌；桥接令牌只取自部署环境；
- 桥接入站按 `(channel, external_message_id)` 幂等，复用既有用户隔离、会话、Outbox 和模型流水线；
- AI 出站按原始渠道与实例回传，继承投递栅栏与错误脱敏策略。

## 已验证

- 单元、API、安全、回调、隔离、Outbox 及渠道适配器测试；
- Ruff 与 Python `compileall` 静态检查；
- 空 PostgreSQL 迁移链、`upgrade → downgrade → upgrade` 验证（v0.3.0 审计修复）；
- `pip-audit` 无已知漏洞（v0.3.0 审计修复）；
- 企业微信文字收发链路（旧验证服务）及新网关正式回调接管。

## 尚未完成或尚未真实联调

- 真实大模型 Provider 全链路联调；
- 实际 ClawBot/微信 Agent 的隔离测试实例联调；个人微信渠道存在平台规则与账号风险，默认保持禁用；
- 图片、语音、文件的安全媒体生命周期与人工客服接管；
- 角色卡多槽位、导入/导出、渠道级切换与完整管理前端；
- Anthropic、Gemini、Ollama、Dify 等 Provider；
- 企业微信发送失败事件闭环；高并发、断网、Redis/PostgreSQL 故障注入及多 Worker 长稳测试；
- 多租户组织、细粒度 RBAC、计费、知识库、MCP/插件、更多渠道和高可用部署。

## 发布判断

- **可作为可靠消息网关与多渠道 P1 基础继续开发。**
- **不应宣称为完整多渠道产品或高可用生产平台。**
- ClawBot 桥接仅在隔离实例、独立凭据与明确合规评估后启用；未配置桥接地址与令牌时个人微信渠道保持离线。
- 面向大规模生产流量前，应完成真实 Provider/渠道端到端联调、发送失败闭环和压力恢复测试。
