# 项目状态与路线图

## 当前版本：0.1.0（基础 MVP）

0.1.0 是可部署、可接管企业微信客服文字回调的基础版本，不代表最初路线图中的全部功能已经完成。

### 已实现

- 企业微信客服回调验签、AES 解密和 URL 验证；
- `sync_msg` 分页拉取、消息幂等、客服账号级游标持久化；
- FastAPI、PostgreSQL、Alembic、Redis Worker；
- 文本消息收发与无模型凭据维护提示；
- 用户身份 HMAC 检索、原始标识加密保存；
- 每用户独立会话、模型名、人设、温度、上下文、最大输出、记忆开关与每日配额；
- `/help`、`/status`、`/model`、`/persona`、`/temperature`、`/context`、`/new`、`/clear`、`/memory`、`/usage` 等命令；
- 单一 OpenAI-compatible Provider 抽象；
- 管理统计、用户列表、消息列表、封禁接口与轻量首页；
- Docker Compose、健康检查、备份、恢复、部署验收脚本。

### 已验证

- 单元/API/安全/回调/隔离测试；
- Ruff 静态检查；
- Docker 镜像和 Compose 部署；
- PostgreSQL 迁移与重启持久化；
- 企业微信真实文字收发链路（旧验证服务）及新网关正式回调接管；
- 无模型 API Key 时的健康运行和维护提示逻辑。

### 尚未完成或尚未真实联调

- 真实大模型 API 回复联调（按部署者要求暂不配置密钥）；
- Anthropic、Gemini、Ollama、Dify 等独立 Provider；
- 企业微信“发送失败事件”的闭环处理；
- 数据库 Outbox、最大重试次数、指数退避、死信队列和人工重放；
- 多 Worker 并发锁、压力测试、断网/Redis/PostgreSQL 故障注入；
- 图片、语音、文件、欢迎语和人工客服接管；
- BYOK 一次性绑定页面及用户密钥托管；
- RAG、pgvector、知识库、MCP 和插件；
- 完整管理后台、细粒度 RBAC、审计查询与配置页面；
- 多租户组织层、计费、多渠道和高可用部署。

## 发布判断

- **可作为基础网关/MVP 部署和继续开发。**
- **不应宣称为功能完整或高可用生产平台。**
- 接入真实模型前，至少应完成供应商联调和微信端端到端验收。
- 面向大规模生产流量前，应优先完成 Outbox/DLQ、发送失败事件、并发锁、压力与故障恢复测试。
